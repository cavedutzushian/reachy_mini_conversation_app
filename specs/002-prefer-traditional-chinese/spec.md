# Feature Specification: 優先使用繁體中文

**Feature Branch**: `feat/002-prefer-traditional-chinese`

**Created**: 2026-10-30

**Status**: Draft

**Input**: User description: "調整顯示與回覆的語言，盡量使用繁體中文，避免使用簡體中文"

## Clarifications

### Session 2026-10-30

- Q: 這次繁體中文調整要涵蓋哪些使用者看得到的內容？ → A: 介面文案、機器人回覆、使用者與助理逐字稿。
- Q: 服務回傳簡體逐字稿時，你希望何時轉為繁體顯示？ → A: 只要求模型優先用繁體，不轉換服務回傳的文字；即時片段與完成後文字均保留原樣。
- Q: 回覆語言設為「自動」時，要保留自動判斷，還是預設改用中文？ → A: 保留自動判斷；回覆中文時才套用繁體偏好，未設定時沿用既有預設，不強制改成中文。
- Q: 繁體回覆的一致性驗收要保留「至少 9/10 次通過」的門檻嗎？ → A: 不設硬性比例；確認繁體偏好已套用，記錄實際回覆效果與限制，不以 9/10 作為結案門檻。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 閱讀繁體中文介面與原始對話文字 (Priority: P1)

使用者能以繁體中文理解自有介面與連線狀態；逐字稿及回覆呈現服務原文，透過模型的繁體偏好減少助理回覆中的簡體，而不改寫辨識結果。

**Why this priority**: 介面及對話是日常入口，統一字形能減少閱讀負擔。

**Independent Test**: 瀏覽啟動、設定、供應商切換、對話、工具結果及連線錯誤六類流程，檢查自有文案與逐字稿。

**Acceptance Scenarios**:

1. **Given** 使用者開啟應用程式，**When** 瀏覽設定、按鈕與狀態，**Then** 自有標題、說明及提示使用繁體中文，產品名稱與必要技術名稱保留原文。
2. **Given** 語音辨識服務回傳簡體中文，**When** 顯示即時與完成後的逐字稿，**Then** 保留服務原文，不進行繁簡轉換；使用者逐字稿仍可能包含簡體。
3. **Given** 工具或連線失敗，**When** 顯示錯誤，**Then** 提供繁體中文原因與可採取動作，同時保留必要原始錯誤資訊。

---

### User Story 2 - 兩個後端都優先以繁體中文回覆 (Priority: P1)

使用者在 Hugging Face 或 Gemini 進行中文對話時，開場、一般回答與工具結果說明都優先採用繁體中文文字，語音維持中文。

**Why this priority**: 僅翻譯介面無法改善實際對話，偏好需適用於兩個已支援後端。

**Independent Test**: 確認每個後端收到正確的繁體回覆偏好，再分別進行中文問答、工具回覆與重新連線，記錄實際效果及限制；不以繁體回覆比例作為通過門檻，並保留人格與聲音設定。

**Acceptance Scenarios**:

1. **Given** 使用中文回覆偏好，**When** 開始任一後端的對話，**Then** 開場與後續中文文字回覆優先使用繁體，語音使用中文。
2. **Given** 使用者以簡體中文提問，**When** 沒有要求特定字形或其他語言，**Then** 回答仍優先使用繁體，不要求使用者先轉換輸入。
3. **Given** 工具結果或人格含簡體內容，**When** 助理說明或回覆，**Then** 一般中文敘述優先繁體，但不改變事實、工具動作或人格特色。
4. **Given** 使用者切換後端、重新連線或重啟，**When** 繼續中文對話，**Then** 語言與繁體偏好持續生效，無須每輪重複要求。
5. **Given** 回覆語言為自動，**When** 依對話決定回覆語言，**Then** 維持既有自動判斷；只有中文回覆優先採繁體，不強制所有回覆使用中文。

---

### User Story 3 - 保留原文與其他語言的正確性 (Priority: P2)

使用者閱讀程式碼、名稱、網址及引用時，不因繁體偏好而損壞內容；明確的其他語言或保留簡體原文要求亦能被尊重。

**Why this priority**: 字形一致不應犧牲原文準確度或使用者的明確要求。

**Independent Test**: 比較混合中英文、技術文字及保留原文案例，並驗證其他回覆語言與失敗時的行為。

**Acceptance Scenarios**:

1. **Given** 回答包含網址、程式碼、路徑、識別碼或指定名稱，**When** 用繁體說明，**Then** 說明優先繁體，這些內容保留原樣。
2. **Given** 使用者要求逐字引用簡體原文，**When** 顯示引用，**Then** 原文保留簡體，周圍說明依目前語言偏好。
3. **Given** 已明確設定非中文回覆語言，**When** 對話或重啟，**Then** 不被繁體偏好強制覆寫；自有介面仍預設繁體中文。
4. **Given** 模型未遵守繁體偏好而回傳簡體，**When** 顯示內容，**Then** 保留服務原文並允許對話繼續，不隱藏文字、不自動重試，也不宣稱該回覆已符合繁體偏好。

### Edge Cases

- 所有服務回傳文字均不做繁簡轉換，包括共用字、多義字、混合英文、數字、表情與引用內容。
- 即時片段可依服務後續事件更新；不得因本功能額外改字、漏字、重複或改變語意。
- 第三方內容與錯誤可能無法翻譯；保留必要原始資訊，提供可用的繁體說明，不偽造翻譯。
- 顯示偏好不改寫既有記憶、歷史、使用者人格或工具參數；識別碼仍精確指向原項目。
- 語音誤聽與字形呈現不同，不把繁體顯示視為辨識正確或固定口音的保證。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 自有介面文案 MUST 預設使用繁體中文，涵蓋導覽、按鈕、欄位說明、狀態、通知及可預期錯誤。
- **FR-002**: 兩個既有後端的中文回覆 MUST 明確以繁體為偏好，適用於開場、一般回答與工具結果說明。
- **FR-003**: 既有「中文」選擇 MUST 採用繁體回覆偏好；「自動」MUST 保留既有語言判斷，僅在回覆中文時套用繁體偏好。未設定時 MUST 沿用既有預設；明確的非中文回覆語言設定 MUST 保留，不強制改成中文。
- **FR-004**: 可見回答、使用者語音逐字稿與助理逐字稿 MUST 保留服務回傳的文字，不做繁簡轉換或翻譯；包含即時片段及完成後文字。繁體偏好只透過模型回覆要求生效，不保證辨識逐字稿的字形。
- **FR-005**: 網址、程式碼、路徑、識別碼、明確指定的專有名稱及要求保留的原文 MUST 保持原樣，不僅為統一字形而改寫。
- **FR-006**: 明確的當次簡體原文、翻譯或其他語言要求 MUST 優先於預設偏好，但不永久更動已存語言設定。
- **FR-007**: 偏好 MUST 在後端切換、重連及重啟後保留，且保持原有人格、聲音、工具權限與供應商設定行為。
- **FR-008**: 已知錯誤的應用程式自有說明 MUST 使用繁體中文；第三方內容與原始錯誤文字 MUST 保留，不自動轉換或翻譯，不隱藏失敗。
- **FR-009**: 模型未遵守繁體偏好時 MUST 顯示原始回覆並允許對話繼續，不得為修正字形自動重試生成或重複執行工具動作。
- **FR-010**: 本功能 MUST 不改寫既有記憶、歷史或人格的原始儲存文字，不改變工具參數或權限，不自動開啟相機或記憶。

### Key Entities

- **回覆語言偏好**：使用者的回覆語言；中文包含繁體優先的期望，與後端、聲音及人格分開理解。
- **可見訊息**：自有介面文案使用繁體；服務回覆與逐字稿保留原文，不加入字形轉換。
- **原文例外**：使用者指定的引用、技術文字或其他語言要求，只影響相關內容，不永久改變偏好。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 啟動、設定、供應商切換、對話、工具結果及連線錯誤六類主要流程中，盤點的自有介面文案全部為繁體中文，必要名稱與原始資訊除外。
- **SC-002**: 兩個後端均驗證收到符合生效語言與當次例外規則的繁體回覆偏好；每後端各十次代表性中文問答作為觀察樣本，涵蓋開場、簡體輸入、一般提問及工具結果。以服務回傳的完成助理文字／逐字稿原文記錄字形效果與語音語言、無有效回覆或無法判斷的情況及服務限制；不設繁體比例或 9/10 的結案門檻，不轉換文字或重試來改善紀錄。
- **SC-003**: 十二組涵蓋簡體、繁簡混合、即時逐字稿及受保護文字的案例中，顯示文字與服務對應片段／完成文字一致；本功能不改字、不漏字、不重複，數字與原意完整保留。
- **SC-004**: 兩個後端的重啟、重連及切換偏好保留案例全部通過，既有非中文語言、人格、聲音與工具權限未改變。
- **SC-005**: 保留簡體原文、其他語言及模型未遵守繁體偏好的案例全部保留原文，對話可繼續，沒有自動重試生成或重複工具動作。
- **SC-006**: 自動模式中各三組中文與非中文對話，以及未設定回覆語言的案例，均保留原有語言選擇規則；中文回覆套用繁體偏好，非中文不被強制改成中文。

## Assumptions

- 這是既有個人客製化的新功能規格，不重開或改寫已結案的 Gemini 驗收。
- 「顯示」經使用者確認，涵蓋自有介面文案、機器人回覆及使用者與助理逐字稿，不包含機器人控制程式、第三方網站、開發者日誌或全專案文件翻譯。
- 介面預設繁體；中文回覆優先繁體，但保留明確非中文設定與當次原文要求，不新增完整多語言翻譯平台的需求。
- 自動模式沿用既有語言判斷，未設定時沿用既有預設；繁體偏好不改變語音辨識的語言選擇或強制所有回覆改成中文。
- 繁體是文字字形與表達偏好，不要求更換聲音、指定新口音或保證每次語音辨識正確。
- 「盡量」以繁體偏好正確套用及實際效果紀錄驗證，不設生成回覆的繁體比例門檻，也不承諾模型永不出現簡體。觀察樣本中的簡體、繁簡共用字、無效回覆與語言偏離均如實記錄，不單憑字形比例判定結案；使用者與助理逐字稿仍保留服務原文。
- 沿用既有後端、語言設定與人格功能；服務驗證仍受帳號、零付費使用及使用者在場條件約束。

# Data Model: 繁體偏好與原文呈現

本功能不增加儲存實體、欄位、設定版本或遷移。以下描述既有資料的使用契約。

## 回覆語言偏好

| 項目 | 來源／值 | 規則 |
|---|---|---|
| 全域語言 | `AppSettings.language`，既有兩字母／auto／未存值 | 未存值沿用環境與既有預設，不改成 zh |
| 人格語言 | `AppSettings.profile_languages`，人格名到語言的對照 | 有效的人格值優先於全域值 |
| 生效語言 | `get_session_language()` | 不改現有解析順序 |
| 繁體回覆偏好 | 暫時性共用指示 | 中文時優先繁體，不是新持久化欄位 |
| UI 語言 | 固定繁體，HTML `zh-Hant` | 與回覆語言分開；不傳作後端辨識代碼 |

`language.set` 仍以 `profile` 或 `all` 範圍儲存，沿用既有全域設定清除人格覆寫的語意。當次請求其他語言不產生任何設定寫入。

## 可見訊息

| 類別 | 可修改內容 | 必須保留 |
|---|---|---|
| 自有固定文案 | 導覽、按鈕、狀態、說明、已知錯誤、輔助名稱 | selector、路由、事件名與操作語意 |
| 服務回覆／逐字稿 | 只修改周圍角色或狀態標籤 | 既有組裝後的文字內容、順序、部分／完成語意 |
| 第三方／使用者資料 | 可加自有繁體標籤或說明 | 名稱、描述、網址、程式碼、輸入與錯誤原文 |

既有 transcript 事件的 `role`、`text`、`final` 與序列資訊不增減或改名；不得增加 converted_text 等平行表示。歷史維持原有原文，不以顯示語言更新既存紀錄。

## 已知錯誤說明

保留既有原因碼作為身份，僅改對應的顯示文案；未知原因仍保留原始訊息。若原訊息含服務細節，沿用既有憑證遮蔽與安全顯示邊界，不為翻譯額外保留或上傳資料。

## 暫時性原文例外

使用者當次要求逐字引用簡體、翻譯或使用其他語言，由共用提示描述例外優先順序。不建立新例外資料庫、不解析後改寫工具參數，也不永久改變回覆語言。

## 狀態轉移

1. 啟動：讀取既有設定，決定生效語言，附加回覆政策。
2. 修改全域／人格語言：依既有儲存與重連流程更新；auto 保留判斷，非中文預設保留。
3. 切換／重連／重啟：由既有工廠重建相同政策，不移轉先前供應商的對話或新增歷史回放。
4. 收到服務文字：原有部分／完成／歷史流程直接使用原文。
5. 模型未遵守繁體：顯示原回覆，記為模型一致性失敗；不自動重新生成、不重做工具。

相機、記憶、聲音、人格原始檔及工具權限均不因本功能狀態而改變。

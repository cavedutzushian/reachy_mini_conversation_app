# Contract: 語言偏好與使用者可見文字

本契約適用於 HF、Gemini、設定 RPC 與自有網頁，沒有新增端點或協定版本。

## 語言與提示

| 生效設定 | 預設回覆行為 | 中文文字政策 |
|---|---|---|
| zh | 預設中文 | 優先繁體 |
| auto | 沿用原有自動判斷 | 若回答中文則優先繁體，不無條件指定中文 |
| 其他有效語言 | 保留指定語言 | 當次要求中文時優先繁體 |
| 未存設定 | 沿用既有解析結果 | 依上述生效值，不寫入新的預設 |

當次明確的引用、翻譯或其他語言請求可覆蓋預設的生成內容；不改設定，也不將文字提示改成辨識／語音合成的新增協定欄位。人格特色與記憶原文保留，預設語言政策不應以絕對的「只能說某語言」抵銷此例外。

## RPC 相容性

- `language.get`、`language.set`、`status.get`／`conversation.status`、`backend.config`、`conversation.history` 等既有方法、請求與回應結構不變。
- `language.set` 的 `language` 與 `scope` 保留既有驗證及語意；不新增 `zh-TW`／`zh-Hant` 作為後端語言代碼。
- `choices` 的代碼與身份不變。前端可將 zh 的顯示名稱標為「中文（繁體優先）」；auto 顯示「自動判斷」，不誤稱為預設中文。
- 保留原因碼、錯誤碼、狀態列舉、識別碼、儲存 key、CSS selector 與路由；不得將 `connected` 等機器值翻譯後傳回。
- 自有 `message` 欄位與 `conversation.context.message` 是人類可讀文案，可譯為繁體；`fresh_context` 等原因身份與續接語意不變。
- 已知錯誤以既有穩定原因碼映射繁體說明；未知／第三方原始內容保留，可有固定繁體前綴。不得把錯誤顯示為成功。

## 介面邊界

- 六類主要流程的自有固定文案均為繁體，包含動態載入、空狀態、確認／取消、重試、tooltip 與無障礙名稱；自有診斷頁固定文案亦包含在內。
- 前端頁面語言標記 `zh-Hant` 只描述 UI，不改選擇的回覆語言。
- 產品／人格／工具 ID、聲音名稱、第三方描述及使用者內容不是可任意翻譯的固定文案。
- 模型用的工具宣告與實際參數不為 UI 翻譯而變更；已知自有工具若有繁體顯示說明，僅影響呈現。
- 既有 root README 更新使用行為與限制；不將整個 README 或開發者日誌列入翻譯工程。

## 原文事件

服務文字沿用既有組裝規則；對每個部分／完成事件，顯示與歷史中的文字不因本功能做繁簡轉換、翻譯、正規化或替代。UTF-8、數字、網址、程式碼、路徑、指定名稱及簡體引用均保留。文字必須安全呈現，不能因原文含標記而執行內容。

部分片段可由服務正常更新；不得加入等待整段才顯示、平行轉換欄位、轉換失敗重試或自動重新生成。助理即使回傳簡體也照常顯示，不作修正字形的工具重播。

## 驗證資料

原文保留的十二組固定案例：

1. 純簡體使用者逐字稿。
2. 繁簡混合的一般句子。
3. 一句分成數個即時片段再完成。
4. 同一回覆的部分文字被服務正常更新。
5. 要求逐字引用的簡體句子。
6. 含英文及數字的句子。
7. 含完整網址與查詢參數。
8. 含程式碼及符號。
9. 含 Windows／Unix 路徑。
10. 含指定專有名稱與 memory_id 等識別碼。
11. 含表情及繁簡共用字。
12. 模型未遵守偏好而回傳簡體的完成回答。

同一套十二組固定資料各自檢查 RPC／歷史與實際瀏覽器的即時／完成／歷史適用路徑。使用既有測試 app／RPC fixture 對實際前端發送模擬事件，不啟動雲端或實體工具；每組記錄輸入、預期、畫面實際文字及比對結果。RPC 成功或靜態檔存在都不能取代畫面比對。歷史路徑以重新載入／取得歷史後的實際顯示驗證。

模型問答的輸入與例外先列出，最後提示定稿後才執行最終十次觀察並記錄來源版本／差異摘要；不設 9/10 門檻。無有效回覆、簡體及無法判斷的情況如實記錄，不能事後轉字或重試改善結果。

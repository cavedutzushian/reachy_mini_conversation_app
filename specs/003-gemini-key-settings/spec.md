# Feature Specification: 設定頁管理 Gemini API key

**Feature Branch**: `feat/003-gemini-key-settings`

**Created**: 2026-11-02

**Status**: Draft

**Input**: User description: "在設定頁新增 Gemini API key 的遮蔽輸入欄位，支援輸入、更新、清除及設定狀態提示，讓使用者不必編輯 .env。保留既有 .env 設定方式作為相容入口。金鑰不得出現在日誌、逐字稿或設定查詢回應中。釐清金鑰保存期限、儲存方式、來源優先順序，以及更新、清除與驗證失敗時的對話行為。Hugging Face 維持預設，不新增自動供應商切換。"

## Clarifications

### Session 2026-11-02

- Q: 設定頁金鑰的保存期限與方式？ → A: 跨重啟保留，使用作業環境受保護的憑證儲存；不可用時明確失敗，不回退成一般明文設定。
- Q: 同時有設定頁與環境來源時的優先順序，及清除後行為？ → A: 設定頁來源優先；成功清除後可回到既有環境來源，明確顯示目前來源，不修改 .env。
- Q: 何時驗證、套用及影響現有對話？ → A: 明確按「驗證並套用」，驗證通過才取代原設定；正在使用 Gemini 時開始新對話，不保證前文保留。失敗保留原設定，若驗證影響連線則明確告知。清除立即停止原 Gemini 連線，若有其他來源也由使用者手動重連；HF 不受影響，不自動切換供應商。
- Q: 在 Reachy Mini Control App 內，Gemini 金鑰應直接輸入，還是開啟獨立的本機金鑰設定頁輸入？ → A: 選 A；一般設定頁顯示狀態與「開啟本機金鑰設定」按鈕，另開受保護的本機頁面輸入；保留既有一般設定操作。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 從設定頁提供 Gemini 金鑰 (Priority: P1)

使用者從現有設定頁開啟獨立的本機金鑰設定頁，輸入 Gemini 金鑰並理解設定及驗證狀態，不必開啟或編輯私密設定檔。

**Why this priority**: 移除首次使用 Gemini 時必須尋找並編輯 .env 的操作門檻。

**Independent Test**: 沒有環境金鑰時，從設定頁按鈕開啟本機金鑰設定頁並提交測試金鑰，驗證通過後使用、重新開啟頁面及重啟 App；不操作私密檔案也能理解目前狀態。

**Acceptance Scenarios**:

1. **Given** 沒有任何來源提供金鑰，**When** 開啟 Gemini 設定區段，**Then** 一般設定頁顯示未設定與「開啟本機金鑰設定」按鈕；獨立本機頁面提供空白遮蔽欄位，不預填任何既存金鑰。
2. **Given** 使用者填入金鑰，**When** 明確提交，**Then** 按「驗證並套用」後，以目前所選 Gemini 服務／模型確認可用性，通過且受保護保存成功才套用；結果顯示狀態，回應不包含金鑰。
3. **Given** 已提供金鑰，**When** 重新整理或重開本機金鑰設定頁，**Then** 顯示狀態與來源，輸入欄位為空，不從服務端取得原金鑰。
4. **Given** 受保護儲存不可用，**When** 提交金鑰，**Then** 明確顯示保存失敗，不宣稱已保存、不使用一般明文設定代替，原生效設定不變。
5. **Given** 使用 Hugging Face，**When** 操作 Gemini 金鑰欄位，**Then** 不自動切換供應商，也不影響原 Hugging Face 對話。

---

### User Story 2 - 更新與清除金鑰，理解對話影響 (Priority: P1)

使用者可替換或清除由設定頁提供的金鑰，提交前知道對目前對話的影響；失敗時能分辨原設定是否保留。

**Why this priority**: 金鑰可能過期、輸入錯誤或需要更換；不能因狀態不明而反覆嘗試或誤以為已停用。

**Independent Test**: 先提供一把測試金鑰，再用另一把、無效輸入及清除操作驗證；覆蓋 Gemini 對話中、已斷線及使用 Hugging Face 三種情境。

**Acceptance Scenarios**:

1. **Given** 已有設定頁金鑰，**When** 輸入新金鑰但尚未提交或取消，**Then** 生效金鑰與目前對話均不變。
2. **Given** 使用者明確提交更新，**When** 更新成功，**Then** 新設定經驗證與受保護保存成功後生效；若目前使用 Gemini，結束原連線並開始新對話，先告知前文不保證保留，HF 對話不變。
3. **Given** 更新或驗證失敗，**When** 顯示錯誤，**Then** 原設定保留且不套用候選值，明確顯示目前來源、連線是否被中斷與下一步，不把網路或額度問題說成金鑰必定無效。
4. **Given** 使用者要求清除，**When** 操作完成，**Then** 停止原 Gemini 連線；成功移除本功能管理的金鑰後，若有環境來源，顯示可使用該來源並等待使用者手動重連，否則顯示未設定；不宣稱已在 Gemini 帳號撤銷金鑰。
5. **Given** 輸入欄位為空，**When** 使用者按更新，**Then** 不把空白當成清除既存金鑰的指令。

---

### User Story 3 - 保留既有環境設定與機密邊界 (Priority: P2)

既有使用者可繼續使用 .env／啟動環境提供的金鑰，並了解目前採用哪個來源；金鑰不因設定頁、錯誤或診斷功能而被顯示或留在一般資料中。

**Why this priority**: 新入口必須與既有部署相容，也不能使私密憑證變成可讀取的設定內容。

**Independent Test**: 交叉測試只有環境來源、只有設定頁來源、兩者同時存在及全部不存在；檢查新增、更新、清除、失敗、重整與重啟的機密邊界。

**Acceptance Scenarios**:

1. **Given** 只有既有環境來源，**When** 啟動並開啟設定頁，**Then** 可繼續使用 Gemini，畫面只顯示已設定與來源，不顯示值。
2. **Given** 兩個來源都存在，**When** 啟動或更新／清除設定頁金鑰，**Then** 使用已套用的設定頁來源；成功清除後才回到環境來源，顯示來源改變且不自動重連，不靜默嘗試其他金鑰來掩蓋驗證失敗。
3. **Given** 任一操作或服務失敗，**When** 查看畫面、日誌、逐字稿、歷史及設定查詢回應，**Then** 都找不到測試金鑰或可辨識其值的片段。
4. **Given** 外部網站或不具設定操作權限的請求，**When** 嘗試寫入或清除金鑰，**Then** 請求不生效，不揭露目前金鑰。

### Edge Cases

- 只有空白的輸入、取消編輯及空欄位提交，不等於清除既存金鑰；清除必須是獨立、明確操作。
- 格式看似合理不等於可用；尚未驗證、驗證通過、驗證失敗及服務暫不可用不得混稱。
- 驗證失敗可能來自認證、模型資格、額度或網路，提示須區分可判斷的原因並移除機密資訊。
- 重新整理或重開設定頁不得回填既存金鑰；App 重啟須保留已套用的受保護憑證，提示須區分已保存、僅輸入及驗證中。
- 受保護保存不可用或讀寫失敗須明確告知，不能悄悄改用一般設定或明文備份。
- 同時提供環境與設定頁金鑰時，清除設定頁來源不得偷偷修改、刪除或顯示 .env 的值。
- 金鑰異動的生效狀態須對應目前這次操作，延遲回來的舊驗證結果不得覆蓋較新的更新／清除結果。
- 執行中金鑰異動不得造成雙重對話或重播先前的工具動作；成功套用後明確標示新對話，不承諾續接舊前文。
- 清除本機設定不等於在供應商帳號撤銷金鑰，也不會清除使用者的其他日常資料。
- 清除中仍保留舊金鑰供刪除追蹤時，阻擋狀態優先；首次設定尚未套用時保留原環境來源或未設定狀態，不使用候選。
- 一般設定頁在既有 Control App 內嵌與遠端入口仍可操作；只有獨立本機金鑰設定頁拒絕內嵌及遠端管理。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 設定頁 MUST 提供繁體中文的 Gemini 金鑰遮蔽輸入、更新、清除及狀態提示；一般設定頁提供狀態及「開啟本機金鑰設定」按鈕，遮蔽輸入、更新與清除由另開的受保護本機頁面完成；保留既有一般設定入口與鍵盤操作，不增加顯示既存金鑰的功能。
- **FR-002**: 已設定金鑰 MUST 不從設定查詢回應回填到欄位；重新整理／重開頁面時欄位為空，完成提交、清除或取消後清掉該次輸入。
- **FR-003**: 狀態 MUST 區分有無生效來源、目前來源、是否已驗證及是否待套用；「已提供／已保存」不得等同「驗證通過／已連線」。狀態與驗證結果須對應目前有效的設定。
- **FR-004**: 金鑰 MUST 不出現在日誌、逐字稿、對話歷史、設定查詢回應、可見錯誤、頁面網址、瀏覽記錄或瀏覽器持久儲存中，不回傳既存值、其片段或可用來辨識該值的提示。本功能管理的金鑰不得放入一般設定資料；僅允許輸入／傳送所需的暫時內容及經確認的憑證保存範圍。
- **FR-005**: 設定頁已套用金鑰 MUST 跨 App 重啟保留，保存於作業環境提供且與目前 App 實例／使用者隔離的受保護憑證儲存。儲存不可用或保存失敗時 MUST 明確告知，不套用候選值、不回退至一般設定、瀏覽器或明文備份；既有環境入口仍須相容。未提交或失敗的輸入不是已保存的金鑰。
- **FR-006**: 既有 .env／啟動環境入口 MUST 保留且不得由本功能修改。已套用的設定頁來源優先，沒有該來源或成功清除後才回到環境來源，並顯示目前來源。只有環境來源的既有部署仍可使用；來源解析 MUST 先檢查清除中或無法確認安全狀態等阻擋情況，再考慮舊設定頁金鑰；即使舊值仍在也不得繞過阻擋。尚未套用的候選不改變原生效來源：原為環境來源則保留環境來源，原無來源則仍未設定。已知設定頁來源存在但讀取失敗時不得當作不存在而靜默改用環境金鑰。
- **FR-007**: 使用者 MUST 以明確提交才變更金鑰，以獨立清除動作移除本功能管理的值；空白提交與取消不得移除既存值，不以固定金鑰前綴或長度宣稱已完成服務驗證。
- **FR-008**: Hugging Face MUST 維持預設；輸入、儲存、更新、清除或驗證 Gemini 金鑰不得自動選用 Gemini 或改變目前 Hugging Face 對話。驗證失敗不得自動改用其他供應商，亦不得靜默嘗試另一個來源的金鑰。
- **FR-009**: 使用者明確按「驗證並套用」後，MUST 先以目前選定的 Gemini 服務／模型確認認證及連線資格，並成功受保護保存，才取代原設定；不能僅以格式或非空值宣稱驗證通過。驗證／保存失敗 MUST 保留原設定，不套用候選值。若驗證會中斷現有 Gemini 對話，操作前須告知，失敗後須如實顯示連線狀態與手動恢復方式；成功套用則開始新對話，不保證保留前文。清除立即停止原 Gemini 連線，其他來源可用時仍須使用者明確重連；不得影響 HF 或觸發自動供應商切換。
- **FR-010**: 認證、資格、額度、網路及保存失敗 MUST 提供不含機密的原因與可採取動作；失敗不得顯示為成功，也不得將一般連線失敗視為金鑰必定無效。
- **FR-011**: 清除結果 MUST 說明本功能管理的值是否已移除、環境來源是否可用及目前連線已停止；清除失敗不得宣稱金鑰已刪除，須顯示保留／未確認狀態與下一步，不自動重連。清除本機值不得聲稱已撤銷供應商帳號中的金鑰。
- **FR-012**: 金鑰管理 MUST 限於目前 App 實例的既有設定使用者，不新增公開或跨裝置共用的憑證管理；本機金鑰設定頁不得內嵌於其他頁面；限制僅適用此頁及憑證管理入口，不得封鎖既有一般設定頁的內嵌或遠端一般操作。遠端或轉送設定頁僅顯示安全狀態及須在 App 所在電腦操作的提示，不取得管理憑證、不傳送金鑰。無關網站及無設定操作權限的請求不得變更憑證或取得值。
- **FR-013**: 金鑰管理 MUST 不更動人格、聲音、語言、記憶／歷史原文與工具權限，不自動開啟相機或記憶，亦不得因驗證而執行機器人工具動作。
- **FR-014**: 單獨驗證金鑰 MUST 僅使用驗證所需資訊，不傳送使用者語音、逐字稿、記憶或人格原文，不播放語音、不執行工具；正式套用後的對話依既有權限與行為進行。

### Key Entities

- **Gemini 金鑰**：僅用於所選 Gemini 服務身分驗證的機密值；不屬於可讀回的一般設定。
- **金鑰來源**：設定頁與既有環境來源；已套用的設定頁來源優先，成功清除後可回到環境來源，設定頁值受保護並跨重啟保留。
- **設定／驗證狀態**：不含機密的存在狀態、來源、驗證結果及是否已生效，用來引導下一步操作。
- **當次異動**：尚未提交、驗證中、已套用或失敗的更新／清除意圖；舊結果不得覆蓋新意圖，也不形成可讀取的金鑰歷史。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在憑證儲存可用且已解鎖時，從已開啟的一般設定頁 Gemini 區段起，使用者能在至多三個明確操作內提交或清除金鑰（包含開啟獨立本機金鑰設定頁，不計輸入字元與等待服務），全程不必開啟或編輯 .env。
- **SC-002**: 輸入、更新、清除、失敗、重新整理及重啟六類情境中，日誌、逐字稿／歷史、設定查詢回應、畫面錯誤及一般保存資料皆不得出現測試金鑰或其可辨識片段；由設定查詢或畫面讀回既存金鑰的次數為零。
- **SC-003**: 只有環境來源、只有設定頁來源、兩者同時存在及全部不存在四種來源組合，在重新開頁、清除與重啟後均符合設定頁優先、成功清除回到環境來源及跨重啟受保護保存政策，狀態不誤導。
- **SC-004**: Gemini 使用中、已斷線及 Hugging Face 使用中三種情境的更新／清除／失敗案例，均符合先驗證再套用、失敗保留原設定、Gemini 新對話及清除後手動重連的政策；沒有自動供應商切換、雙重回覆、工具重播或未告知的來源改用。
- **SC-005**: 錯誤金鑰、服務暫不可用及憑證保存失敗均能提供不含機密且可採取行動的提示；原設定是否保留及目前連線狀態可由畫面明確辨識，不以外部服務可用性保證作為本功能承諾。

## Assumptions

- 延續使用者已授權的個人客製化範圍；此階段只建立規格，不讀取實際金鑰、不連線驗證，也不變更已結案的功能。
- 使用者已持有自己的 Gemini 金鑰與服務資格；金鑰申請、計費管理、額度提升、供應商端撤銷與額外供應商不在範圍內。
- 沿用現有 App、SDK 與本機控制／設定使用方式；不新增帳號或公開遠端憑證管理功能。保護設定操作來源的具體設計留待計畫階段。
- 保存採使用者確認的跨重啟受保護憑證儲存；本規格不選定套件、檔案格式或儲存產品。若實作需要新依賴，須先明列影響。
- 介面維持繁體中文；既有其他服務與人格行為保持相容。實作及必要文件更新仍依專案規則，不能將舊功能的測試結果當成本功能驗收。
- 後續本機開發以前置實作與必要離線自動測試完成為依據；尚待使用者配合的人工畫面、平台或服務驗收須分開追蹤，不阻擋無關後續開發，也不得視為已通過或據此宣告完整結案。
- 若將來要向上游貢獻，仍需遵守 Issue／維護者討論與人工審閱流程，本次不自動建立 PR。

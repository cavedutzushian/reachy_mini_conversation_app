# Feature Specification: 單一預建文件 RAG 工具

**Feature Branch**: `feat/004-single-document-rag`

**Created**: 2026-11-04

**Status**: Draft

**Input**: User description: "新增工具使用 chroma+BGE-M3(on CPU) 來讓 Reachy Mini 在對話時能使用 RAG 取得指定的唯一一份文件內容，文件會在事先轉換為嵌入索引後儲存為檔案供使用，在對話時不會建立任何索引，工具沿用現有的 Tool 介面（範例：src/reachy_mini_conversation_app/tools/idle_do_nothing.py）。"

## Clarifications

### Session 2026-11-05

- Q: 停止 App 時，若本機文件檢索仍卡住，最多等待多久回收檢索工作行程？ → A: 最多 9 秒：正常關閉等 5 秒、要求終止後等 2 秒、必要時強制結束後再等 2 秒；此期限僅涵蓋 RAG 工作行程，不是整個 App 的關閉時間。
- Q: 文件查詢超過十秒、但仍在同一輪對話時，應如何告知逾時？ → A: 只顯示一次文字提示，不播放語音；背景晚到答案永久丟棄。若已插話、取消或切換對話，舊文字提示也不再投遞，不自動重試。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 依唯一指定文件回答並提供來源 (Priority: P1)

使用者事先指定一份文件的預建索引，在對話中要求 Reachy Mini 依文件回答。Reachy 取得相關原文段落，使用繁體中文整理答案並提供可核對的來源。

**Why this priority**: 讓回答依據可控、可追溯，不必每次口頭提供文件內容。

**Independent Test**: 使用一份含已知答案及章節定位的預建索引，以原詞及不同說法提問，核對答案、引用與來源範圍；不依賴文件解析或索引建置功能。

**Acceptance Scenarios**:

1. **Given** 索引有效且目前人格允許工具，**When** 使用者要求依文件回答其中有記載的問題，**Then** 取回支援答案的原文，文字回答附文件名稱及章節或其他真實定位，語音簡短說明來源。
2. **Given** 文件與提問採不同詞彙但意義相近，**When** 使用者換句話提問，**Then** 仍能取得支援答案的段落，不要求使用者知道文件原詞。
3. **Given** 已配置唯一文件，**When** 要求查另一份文件、其他路徑或未提供的來源，**Then** 不存取其他資料，明確說明本工具的來源範圍。
4. **Given** 查詢命中相關段落，**When** 提供工具結果，**Then** 只提供有上限的原文及來源，不回傳整份文件、向量或本機絕對路徑。
5. **Given** 工具未啟用或使用者進行一般聊天，**When** 不需要依文件回答，**Then** 原有對話仍可進行，不強制每輪檢索或改變供應商。

---

### User Story 2 - 無答案或索引故障時仍能繼續對話 (Priority: P1)

使用者能分辨文件沒有答案與工具不可用，工具失敗不會中斷語音對話，也不會在對話期間臨時建立索引。

**Why this priority**: 避免以猜測冒充文件內容，並保護既有對話可用性。

**Independent Test**: 分別測試無答案問題、缺失／損壞／不相容索引、混合文件來源及延遲查詢，確認明確結果、文件索引未被改動，且後續一般對話正常。

**Acceptance Scenarios**:

1. **Given** 索引有效但沒有足以支持答案的段落，**When** 使用者問未記載事項，**Then** 明確表示未找到文件依據，不以常識或其他來源冒稱該文件的內容。
2. **Given** 索引缺失、不可讀、損壞或不相容，**When** 查詢，**Then** 回報來源不可用，不建立空索引、重新嵌入或改用其他文件，一般對話仍可繼續。
3. **Given** 索引混合多份文件或同文件多個版本，**When** 驗證來源或查詢，**Then** 拒絕作為有效來源，不任選其中一份回答。
4. **Given** 模型未就緒或查詢超過等待上限，**When** 工具不能完成，**Then** 分別回報未就緒或逾時；逾時且原回合仍有效時只顯示一次文字提示，不播放語音。若原回合已因插話、取消或切換失效，連舊提示也不投遞；背景晚到答案永久丟棄，不自動重送，使用者可明確再次查詢。
5. **Given** 命中段落含執行動作、改設定或洩漏資料的指令，**When** 該內容被取回，**Then** 僅視為參考原文，不因此取得任何額外動作授權。
6. **Given** 部署者已停止 App 並更換完整預建包，**When** 重新啟動並要求依文件回答，**Then** 只使用新包指定的唯一文件版本，來源與引用同步更新，不重用舊查詢結果或在啟動時重建索引。

---

### User Story 3 - 跨後端使用並結束過期查詢 (Priority: P2)

同一份文件可供既有 Hugging Face 與 Gemini 使用；插話、切換供應商或開始新對話後，不會收到前一輪查詢的遲到回答。

**Why this priority**: 與現有即時對話及工具權限一致，不增加第二套對話控制方式。

**Independent Test**: 兩後端分別啟用同一工具並查同一文件，再於慢查詢期間中斷或切換，核對來源、舊結果退役及後續對話。

**Acceptance Scenarios**:

1. **Given** HF 或 Gemini 已選用且具備工具權限，**When** 查詢相同文件問題，**Then** 都可使用同一工具與文件，無須另一套文件服務帳號；HF 預設及供應商選擇不變。
2. **Given** 查詢尚未完成，**When** 插話、取消、換後端或開始新對話，**Then** 舊結果不觸發遲到語音／文字回答或其他動作，也不重新連線或重送原請求。
3. **Given** 查詢已逾時或取消但背景工作尚未釋放資源，**When** 又收到查詢，**Then** 不累積無界限工作；無法處理時回報忙碌，允許之後明確重試。
4. **Given** 目前人格停用文件工具，**When** 要求查詢，**Then** 不讀取文件內容，沿用既有工具權限及錯誤處理。

### Edge Cases

- 空白、只有標點、超過 500 個 Unicode 字元或不支援的查詢：拒絕無效輸入，不改動索引。
- 索引僅含向量，缺少原文、文件版本或定位：不得當成可引用的有效來源。
- 同名但內容或版本不同的文件：只使用指定身分與版本，不合併或自動選用。
- 表格、否定語句、日期、數字或單位需要鄰近上下文：資料不足時說明不足，不拼湊矛盾結論。
- 低相關命中：不把檢索距離當成正確率百分比，也不強行回答。
- 磁碟唯讀、引擎無法開啟或索引需遷移：回報不可用，不以建立／遷移文件索引修復。
- 原文件已移走但索引包含必要原文及定位：不要求重新讀入、解析原文件。
- 網路或對話供應商斷線：本機檢索不另用網路，沿用既有對話恢復行為，不自動換供應商或重送文件段落。
- 停止 App 時檢索仍未完成：撤銷舊查詢結果的投遞資格，最多九秒等待回收工作行程；仍無法確認已退出時，安全記錄清理未完成並保留工作副本，不無限等待，也不修改原始索引包。
- 逾時與插話／取消／切換同時發生：文字提示投遞前仍須確認原回合有效；失效則不顯示。背景答案的投遞資格在逾時時即永久失效，不能因仍在同一回合而恢復。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 提供受現有工具權限控制的文件查詢能力，供 HF 與 Gemini 共用；一般對話不因此強制查詢、換供應商或新增機器人動作。
- **FR-002**: 每個啟動實例 MUST 只接受指定文件的一個有效版本；問題輸入不得改選路徑、文件、集合或網路來源，混合多文件／多版本的來源 MUST 拒絕。
- **FR-003**: 系統 MUST 使用事先提供的完整索引資料，包括檢索表示、原文、文件身分／版本及真實定位；不得憑向量猜測原文或編造頁碼。
- **FR-004**: 系統 MUST 檢查預建包的相容條件、來源一致性與必要資料；缺失或不相容時回報來源不可用，不自動選用其他包。
- **FR-005**: App 執行期間 MUST NOT 建立、匯入重建、更新、遷移或補建文件檢索索引；不得在對話中解析原文件來產生段落／向量，也不得以建立空集合掩蓋來源缺失。
- **FR-006**: 系統 MUST 先檢查收到的原始問題字串不超過 500 個 Unicode code points（含前後空白），再去除前後空白檢查有效內容；超出上限回報輸入無效，不先裁切或以去空白規避上限。有效問題在本機 CPU 上取得與文件向量設定一致的查詢表示，不得改用雲端 embedding、其他模型或自動下載模型／tokenizer 完成請求。HF 與 Gemini MUST 使用相同驗證順序。
- **FR-007**: 成功結果 MUST 附原文、文件名稱、版本、定位及索引版本；每次最多三段、原文合計最多 2,000 個 Unicode 字元。裁切須明示並保留定位，不可拼成不存在的原句。
- **FR-008**: 依文件回答時 MUST 先查工具，根據結果作答；文字附來源，語音簡短指明來源。答案盡量使用繁體中文，引用保留文件原文，不為轉換字體而改寫引文。
- **FR-009**: 依據不足時 MUST 明確表示未找到足夠文件內容，不把常識或其他來源冒充此文件答案；與文件無關的一般對話仍可依既有行為進行。
- **FR-010**: 未就緒、忙碌、來源不可用、輸入無效、沒有依據與逾時 MUST 可被區分；預期操作失敗依既有工具方式記錄安全錯誤並回傳錯誤結果，不使對話迴圈退出。
- **FR-011**: 單次有效查詢 MUST 在十秒內完成或產生逾時結果；原回合仍有效時，逾時只顯示一次文字提示，不播放語音或觸發語音後續回覆。此提示的投遞資格與背景答案分開判斷：逾時即永久撤銷背景答案的投遞資格，只有一次逾時文字可在原回合仍有效時顯示；若已插話、取消、換供應商或開始新對話，提示也不投遞。CPU 檢索不得阻塞音訊及插話處理，不自動重送，背景工作不得無界限累積。停止等待不代表已強制終止背景運算，原工作未完成前仍占用工作槽。
- **FR-012**: 插話、取消、換供應商、結束對話或既有工具退役條件發生後，舊查詢 MUST 不產生遲到回覆或動作，也不將舊結果帶入新對話。
- **FR-013**: 查詢 MUST 不修改長期記憶、人格、語言、語音、相機、其他工具權限或供應商設定；文件文字不得取得超出原要求及既有權限的動作授權。
- **FR-014**: 本機文件索引及問題 embedding MUST 不送往外部服務；只有回答所需的有界段落及來源可經既有工具結果傳給目前對話供應商。本次查詢的工具呼叫與診斷日誌 MUST 不記錄完整查詢、文件段落、向量或本機絕對路徑；既有逐字稿政策保持不變，不自動將文件寫成長期記憶。
- **FR-015**: 部署者 MUST 能以既有配置方式指定唯一索引包，以停止 App、更換預建包、重新啟動的方式更新文件；本功能不新增上傳、索引管理頁面或對話內熱更新。
- **FR-016**: 停止 App 時，系統 MUST 先撤銷所有 RAG 查詢的投遞資格，再最多等待九秒關閉並回收 RAG 工作行程：正常關閉最多五秒、要求終止後最多兩秒、必要時強制結束後最多兩秒。提前退出即可進入下一個清理步驟，不必等滿；此期限不包含 App 其他元件的關閉時間。只有確認工作行程已退出才清除其工作副本；逾期仍未確認時記錄清理未完成並保留副本，不改動原始索引包。

### Key Entities *(include if feature involves data)*

- **指定文件**：唯一來源的身分、名稱及版本；同時只有一個有效版本。
- **預建索引包**：該文件的檢索資料、必要原文與定位、索引版本及建置時的相容條件；在 App 外部事先產生並提供。
- **文件段落**：屬於唯一文件版本，具有穩定識別、原文及真實定位；可能需要鄰近上下文才能支持答案。
- **文件查詢**：問題、所屬對話／工具生命週期及完成或失效狀態；不能指定其他文件。背景答案失效、原回合是否有效及一次性逾時文字是否已投遞須分別追蹤，不能以單一失效旗標同時抹除應顯示的逾時文字或放行晚到答案。
- **檢索結果**：有上限的原文段落與來源、索引版本，或明確的無依據／失敗狀態；不代表文件內容已取得動作授權。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 對唯一文件人工標註的 20 題可答問題（至少 10 題採不同於原文的說法），至少 18 題取回能直接支持答案的原文；HF、Gemini 各至少 18 題回答符合原文，所有文件依據型回答都能核對來源。
- **SC-002**: 對 10 題無依據問題及 5 題要求其他文件的問題，兩後端均不捏造文件答案，未授權來源取用次數為零。
- **SC-003**: 在驗收前記錄並固定的一台 CPU 主機上，以最多 1,000 段、每段最多 512 tokens 的預建測試文件及 50 次最多 200 字的有效問題評估；資料與模型就緒後，至少 48／50 次查詢須在五秒內成功提供文件段落（達到至少 95%），所有查詢在十秒內完成或明確失敗。錯誤、無依據、忙碌、未就緒與逾時即使很快回傳，也不得計入五秒成功數；不得排除失敗題後縮小分母。資料量只固定效能樣本，不是文件功能上限。
- **SC-004**: 兩後端各進行 10 次查詢，期間涵蓋 5 次插話及 5 次取消、換後端或開始新對話，App 非預期退出及舊結果觸發遲到回覆／動作次數均為零，後續一般對話可繼續。
- **SC-005**: 缺失、損壞、不相容、混合文件、缺原文／定位、模型未就緒、忙碌及逾時八類測試均有明確結果，後續一般對話正常；無文件索引建立／變更、模型下載或雲端 embedding 請求。
- **SC-006**: 有效與失敗測試中的工具結果均符合段落／文字上限與來源範圍；診斷日誌不含置入測試問題／文件的專用原文標記。既有逐字稿的正常回答與引用不列入診斷日誌檢查。

## Assumptions

- **使用者指定限制**：Chroma、BGE-M3、CPU 與既有 `Tool`／`ToolDependencies` 合約為輸入要求；參照 `idle_do_nothing.py` 接入方式，不是本規格自行增加的框架選型。套件、版本與接線留待計畫。
- **預建交付**：「儲存為檔案供使用」解讀為完整本機索引包，可含多個必要儲存檔案，但只對應一份文件的一個版本；不要求物理上只有一個檔案。外部建置者提供必要原文、定位及相容資訊，原文件解析／建置流程不屬於本功能。
- **模型供應**：文件與查詢使用相同 BGE-M3 revision、tokenizer、向量處理及相似度設定，模型檔事先可用；查詢時仍需計算問題向量。相容驗證方式由計畫定義。
- **使用方式**：首版為單人、單實例、一次一個有效查詢；明確要求依文件回答時查工具，一般聊天不強制檢索。不新增文件選擇介面、多人授權或替代對話服務。
- **只查詢範圍**：禁止文件內容、文件向量及檢索索引的建立／變更，不將引擎必要鎖或執行期記錄檔等同於文件重建；不得藉此遷移資料。原包保存、工作目錄及開啟相容性由計畫處理。
- **初始預設**：問題 500 字元、結果三段／2,000 字元、十秒等待及效能樣本為未指定細節的規劃預設，並非已實測效能；主機及資料於驗收前固定，相關度門檻以標註題校準，不當成可信度百分比。
- **資料流**：部署者有權使用文件，啟用前了解命中段落會傳至已選供應商；本機檢索不需要另一個雲端帳號。既有憑證、記憶、相機及供應商預設保持不變。
- **不在範圍**：建索引／匯入工具、文件解析、OCR、原文件上傳、編輯／刪除文件、多文件／多版本切換、熱更新、雲端 embedding、混合／多向量檢索、重排序、模型訓練及自動供應商切換。
- **交付治理**：延續個人客製化規劃，本輪只寫規格、不開上游 PR，不安裝依賴或執行模型；後續計畫須列明 Chroma 與 embedding 執行依賴、CPU 及跨平台影響，依憲章於新增前提出。

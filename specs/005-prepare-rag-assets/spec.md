## Clarifications

### Session 2026-11-06

- Q: 新版本已完成驗證並放到正式位置後，如果刪除舊備份或暫存失敗，腳本應如何回報? (I1) → A: 保留已驗證新版，回報「已發布，清理未完成」，結束碼 8；保留恢復／清理資訊，不自動回復或重跑。發布前失敗的舊素材零變更要求不套用到此發布後狀態。

### Session 2026-11-09

- Q: 兩個模型應分別執行下載腳本準備，還是由一次命令同時備妥？ → A: 同一下載腳本每次明確指定嵌入或重排模型，分別執行兩次，再執行一次產包，共三個手動步驟。每個目的地獨立驗證、發布及回報結果，保留完整就緒模型的重用及發布後清理結束碼 8。
- Q: 執行產包時，要明確選取這套已決定的實驗設定，還是未指定時自動使用它？ → A: 必須明確選取這套版本化完整方案；未選取就停止。選取後自動帶入全部既定參數，不必逐項輸入；包內保存選值來源與已知限制，不宣稱新文件已校準。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 下載一次即可離線使用的指定模型 (Priority: P1)

部署者以同一下載腳本分別指定嵌入與重排角色及固定版本，準備 BGE-M3 與 BGE-base；每次只處理一個模型目的地，不必自行挑選、搬移或修補檔案。

**Why this priority**: 文件產包與查詢需要相容且版本可驗證的嵌入模型，完整查詢還需要對應的重排模型，避免把其中一個就緒誤當成整套素材已備妥。

**Independent Test**: 各模型下載後斷網，依其角色分別驗證 CPU 載入、有效向量或有限的原始重排分數，不需要真實文件、對話服務或機器人，也不要求通過檢索品質比例。

**Acceptance Scenarios**:

1. **Given** 模型目的地尚不存在且可連線至公開模型來源，**When** 部署者明確指定一個模型角色與合法固定版本並執行下載，**Then** 該完整模型通過角色對應的離線檢查後才發布，顯示實際角色、版本、位置與完成狀態，不連帶下載或發布另一個模型。
2. **Given** 相同位置已有完整且版本相同的模型，**When** 重複執行相同要求，**Then** 核對檔案後回報已就緒，不重新下載或覆寫。
3. **Given** 已有其他版本或不完整模型，**When** 未明確要求替換，**Then** 拒絕覆寫並告知原因；明確替換時，新模型驗證失敗不得改動既有模型。
4. **Given** 下載中斷、空間不足、版本不存在或必要檔案缺失，**When** 無法完成準備，**Then** 明確失敗，不把半成品當可用模型，不改用其他版本或模型。
5. **Given** 只有嵌入或重排其中一個模型已就緒，**When** 檢查整套素材準備狀態或進行完整產包驗證，**Then** 明確指出另一角色尚未備妥，不把單一模型的成功宣告為整套查詢就緒，也不修改已驗證的模型來處理另一角色的失敗。

### User Story 2 - 將唯一文字文件產成 App 可讀的完整包 (Priority: P1)

部署者提供一份 TXT／Markdown、文件識別資訊及可追溯的選用方案設定，手動執行離線產包腳本，取得含原文、真實定位及完整預建檢索資料的新版索引包，不必手工編輯包資訊或操作索引資料庫。不要求以品質通過證明換取產包資格。

**Why this priority**: 補齊現有文件工具缺少的素材準備步驟，讓使用者能以指定文件進入既有驗收流程。

**Independent Test**: 使用完整本機兩模型及無敏感資料的固定文件，在禁止對外連線的環境產包；由符合 004 新版合約的讀取端重新開啟並執行完整檢索／重排，核對有界原文、位置及素材不變性，不以實際對話或機器人操作代替素材驗證。

**Acceptance Scenarios**:

1. **Given** 有效文字文件、相容的本機兩模型、必要文件資訊及完整選用設定，**When** 執行產包，**Then** 取得符合 004 新版合約的完整包，只包含該文件版本，原始文件與模型不被修改；不產出或默默轉換舊 v1 包。
2. **Given** 文件含繁體中文、否定條件、表格、程式碼、超連結或操作指令，**When** 切段與產包，**Then** 原文可逐段核對，文字不被執行、翻譯、讀取連結或當作額外授權。
3. **Given** 文件沒有頁碼，**When** 產生定位，**Then** 使用原始行範圍；Markdown 可附原有章節名稱，不編造頁碼。無標題 TXT 視為單一文件範圍，按原始段落與長度離線切分，以文件名稱及真實行號作來源，不要求補造章節。
4. **Given** 相同來源 bytes、識別資訊、切段／別名與策略設定，**When** 產包兩次，**Then** 段落內容、順序、ID、定位及預建 BM25 資料一致，不要求引擎索引二進位逐位相同。
5. **Given** 任一必要模型缺失或不相容、方案設定不完整／無效、文件無有效文字或編碼無效，**When** 執行產包，**Then** 明確失敗，不連網下載、不改動既有包、不退回舊流程或放寬驗證掩蓋問題。
6. **Given** 未提供額外別名，**When** 離線產包，**Then** 只使用文件名稱／原有章節標題並明示空別名清單，不自動擷取或生成別名；有人工清單時逐項核對同一文件／版本的原文定位及對應來源範圍，不符即拒絕。
7. **Given** 其他必要資料已備妥，**When** 未明確選取版本化方案就執行產包，**Then** 停止並提示選取，不套用預設方案、不發布或改動既有包；明確選取後帶入完整既定參數並保存其來源與限制，不要求逐項輸入或品質通過證明。

### User Story 3 - 安全發布素材並交接給 App (Priority: P2)

部署者在 App 停止時發布新素材，知道已完成及未完成的驗證，並依腳本顯示的路徑手動設定既有文件工具。

**Why this priority**: 保留已可用的素材，避免將半成品或尚未驗證的平台誤當成已就緒版本。

**Independent Test**: 以既有目的地測試拒絕覆寫、明確替換及失敗／中斷情境；不需啟動實際對話。

**Acceptance Scenarios**:

1. **Given** 從不同工作目錄啟動，**When** 使用預設目的地完成準備，**Then** 素材仍位於儲存庫約定位置，保留既有嵌入／索引路徑並另顯示獨立重排模型路徑的實際設定值，不修改 `.env`。
2. **Given** 包已存在，**When** 未要求替換，**Then** 拒絕覆寫；明確替換時先通過候選包檢查，再發布完整新包。
3. **Given** 候選包無法通過重新開啟、查詢或不變性檢查，**When** 檢查結束，**Then** 不發布為可用包、不標記完成，不修改讀取合約掩蓋問題。
4. **Given** 只在 Windows 完成驗證，**When** 發布相容資訊，**Then** 只列實際通過的 Windows／架構組合，不把略過的 Linux／macOS 寫成已驗證。
5. **Given** 已驗證新版已放到正式目的地，**When** 刪除舊備份或暫存失敗，**Then** 保留新版，明確回報「已發布，清理未完成」及結束碼 8，留下恢復／清理資訊，不自動回復舊版、重新下載或重新產包；不得當作一般發布前失敗自動重試。

### Edge Cases

- 空白／無有效文字、無效 UTF-8、UTF-8 BOM、CRLF／LF、大小寫副檔名；不支援的格式、資料夾、萬用字元、多文件及 URL。
- 超長單段、重複章節、沒有標題、表格及程式碼；Markdown 的外部連結、圖片、HTML 與嵌入指令。
- 人工別名清單為空、別名不在原文、來源定位／版本不符或錯配章節；不得以推測、模型生成或讀取其他文件修補。
- 浮動模型版本、必要檔案缺失／損壞、不支援檔案或連結、下載暫存資料，以及無可證明的模型 revision。
- 模型角色未指定、以嵌入模型冒充重排模型、只有其中一個就緒或模型配置缺漏；每次模型準備只影響其指定目的地，另一角色須由使用者另行準備。
- 下載中斷、離線卻缺模型、空間不足、權限不足、突然終止及同目的地並行準備。
- 已存在但未允許替換的目的地、來源／模型／輸出互相重疊、根目錄或連結轉向；App 仍在使用素材。
- 索引無法完整持久化、BM25／來源脈絡資料缺失、套件版本不相容、方案設定來源不明，或將模型載入／產包成功誤當成文件品質與語音驗收通過。
- 舊 v1 包或過去只提供單一距離值的設定：不能冒充本輪新版混合檢索／重排包，須由使用者在 App 外提供原文件及完整設定重新產包。
- 已驗證新版已發布，但舊備份／暫存清理失敗：這是已發布但待清理狀態，與尚未發布的失敗分開判定。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 提供分開由部署者手動執行的模型下載與單文件離線產包腳本。同一下載腳本每次明確指定一個模型角色，分別準備嵌入及重排模型後再產包，共三個手動步驟；不提供一次準備兩模型的彙總發布流程。不在 App 啟動、對話、Tool 或故障修復流程自動執行，不新增管理頁面。
- **FR-002**: 下載只支援嵌入 `BAAI/bge-m3` 與重排 `BAAI/bge-reranker-base`，每次明確指定角色與 40 位 commit revision，且須符合選用方案的固定版本。本輪嵌入為 `50f9396f75618b3389c1fd1068a1ff58dc7b5b26`、重排為 `2cfc18c9415c912f9d8155881c133215df768a70`。拒絕浮動分支、tag、其他模型、任意下載 URL 及不相容版本；僅下載階段允許連線至公開模型來源及其必要檔案服務，不自動換模型或版本。
- **FR-003**: 下載須供應該角色完整的安全權重、tokenizer 與配置，排除不被接受的格式、連結及下載暫存資料。發布前以無網路、無遠端程式碼的條件驗證 CPU 載入：嵌入模型產生合規向量，重排模型對固定非敏感配對輸出有限原始分數；不要求重排分數通過品質比例。附可離線核對的角色、模型 ID、不可變 revision、驗證條件與檔案完整性資訊，不只相信資料夾名稱。相同完整版本重跑時核對後直接回報就緒，不重新下載；各角色沿用 FR-011 的獨立目的地發布規則，不把單一角色成功宣告成兩模型均就緒。
- **FR-004**: 嵌入模型、重排模型及包的預設位置分別為儲存庫的 `external_content/bge-m3-model/`、`external_content/bge-reranker-base-model/`、`external_content/document-package/`，不隨啟動工作目錄漂移；允許明確指定其他本機目的地。保留既有嵌入／索引路徑配置，新增獨立重排模型路徑；完成時顯示實際位置與對應設定值，由使用者明確配置，不修改 `.env`、一般設定或憑證庫，也不搬移已有模型。
- **FR-005**: 產包只接受一份 `.txt`、`.md` 或 `.markdown` 本機常規檔案，副檔名不分大小寫；接受 UTF-8 及 UTF-8 BOM，其他編碼拒絕，不自動轉碼。拒絕其他格式、目錄、批次、多文件及 URL，不展開連結、圖片、HTML 或外部內容。
- **FR-006**: 產包要求文件 ID、顯示名稱、文件版本、索引版本及使用者明確選取的版本化完整方案，依 004 新版合約驗證；未選取方案就停止，不自動套用預設方案。選取後自動帶入 FR-015 的全部既定參數，不要求逐項輸入；包內保存方案版本、選值來源與已知限制。設定缺漏、無效或與讀取策略不相容時失敗。不再要求使用者提交已通過召回／段落支持率／零檢索誤放行的校準證明；須區分使用者採用的實驗設定與已實測結果，不把方案選取或 reference 宣稱為新文件校準成功。來源摘要依指定原始檔案 bytes 計算，來源檔不被改動。
- **FR-007**: 切段保留原文、順序、可重現的安全 ID 及真實原始行範圍；不翻譯、改字體、重寫或編造定位。依來源章節及長度離線切分，過長內容分段而非靜默省略；切段與重疊規則須固定、版本化且與 004 模型輸入策略相容，同一設定可重現。無標題 TXT 視為單一文件範圍，按原始段落與長度切分，使用文件名稱及真實行號，不要求新增章節標記；Markdown 只取原有章節名稱，無頁碼不生成頁碼。額外別名只接受使用者提供的可選清單，逐項核對同文件／版本的原文定位及對應來源範圍；無清單則明示空清單，只用文件名稱／來源標題，不自動擷取正文別名、補同義詞或使用模型／雲端生成。來源脈絡與可引用原文分開，不把別名當答案。
- **FR-008**: 產包及發布前驗證使用預先準備且 revision／完整性可驗證的本機嵌入及重排模型，沿用 004 的 CPU 相容條件；任一必要模型缺失或不相容時失敗。所有文件向量、BM25 詞彙／統計與文件檢索索引均於本流程離線預建、完整保存；App 啟動／對話／故障恢復不得補建。禁止本流程下載模型、雲端嵌入、替代模型、額外雲端審核及對外傳送文件、段落、問題或向量。
- **FR-009**: 產出與 004 同步定義的新版本包格式及完整 schema：唯一文件版本與集合，包含原文、定位、向量、預建 BM25 資料、標題／可選人工別名與其來源證據、模型與檢索／重排設定、策略版本、實際完整套件版本、所有必要檔案及雜湊。包格式須可與舊 v1 明確區分；新版讀取端拒絕舊 v1 並提示離線重產，不維護舊 dense-only 流程，也不自動轉換／遷移。產生固定非敏感 reference 問題及對應向量以驗證編碼一致性，不代表回答品質已通過。[包合約](../004-single-document-rag/contracts/index-package.md) 與 [schema](../004-single-document-rag/contracts/index-manifest.schema.json) 已完成本輪 v2 設計同步；產品實作及Windows素材驗收的實際結果見[驗收指南](quickstart.md)，不以放寬完整性驗證或錯標版本掩蓋不相容；005完成不代表004執行期驗收通過。
- **FR-010**: 候選包須由符合 004 新版合約的讀取端在獨立離線驗證中重新開啟，使用兩模型執行完整混合檢索／重排並核對不變性後才發布；驗證結果須區分正常有界結果、無命中與操作失敗，不把有無命中或分數高低當成品質通過證明。檢查須證明原包、原文、定位、向量、筆數、BM25 資料及持久索引沒有被讀取端變更，無待重放寫入、修復或重建。只列入實際驗證的平台／架構；讀取端或新版合約未備妥時不得宣告 App 可讀就緒，也不以程序退出或完整性宣告代替證據。
- **FR-011**: 模型及索引目的地預設不得覆寫，明確要求替換才可處理；先驗證候選素材，再發布。已驗證新版放妥正式目的地即為發布界線；發布前可處理的下載、驗證及寫入失敗須保留既有可用版本。發布後清理舊備份／暫存失敗時，保留已驗證新版，回報「已發布，清理未完成」及結束碼 8，保留恢復／清理資訊；不得自動回復、重新下載、重新產包或當作一般失敗自動重試。突然終止不得把半成品宣告完成，須能辨認殘留並提供恢復／清理指引。只處理本次擁有的暫存，不刪無關內容；同目的地並行準備須拒絕。
- **FR-012**: 拒絕來源文件、產包所用模型與輸出間的危險重疊、不應替換的根目錄及連結轉向；FR-011 明確允許的目的地版本替換不在此拒絕範圍。部署者在 App 停止時替換素材，腳本不得自行停止、啟動或喚醒 App／機器人。
